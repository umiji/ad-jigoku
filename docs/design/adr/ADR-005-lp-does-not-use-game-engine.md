# ADR-005: LP はゲームエンジンを使わない

- Status: Proposed
- Date: 2026-09-12
- Drivers: AD-10

## Context

LP は「広告を閉じると次の説明に進む」構造で、ゲームと見た目がほぼ同じである (DESIGN_REQ §4.1)。
「エンジンを共有すれば早いのでは」という発想が自然に出る。

## Decision

LP は `packages/game-engine` を使わない。共有するのは `packages/ui` と `packages/pattern-catalog` のみ。
LP 側は 100 行程度の `LpFlow` reducer で進行を管理する。

## Rationale

| | LP | Game |
|---|---|---|
| 進行 | 台本（固定順序） | seed による生成 |
| 失敗 | ない | ある |
| リソース | ない | patience / score / time |
| 目的 | 物語を伝える | 遊ばせる |

LP をエンジンに載せると、エンジンに「失敗しないモード」「順序固定モード」
「リソース無効モード」が入り込む。それは決定論テストの分岐を増やし、
ADR-002 の価値を削る。

## Consequences

### 良い
- エンジンが「ゲームのためだけ」の純度を保つ
- LP の実装が軽い（初期 JS 予算 120KB を守りやすい）
- LP とゲームを独立にデプロイ・改修できる

### 悪い
- ポップアップの挙動ロジックが2箇所に存在しうる

### 緩和
- 挙動のうち視覚・入力に属する部分は `packages/ui` のコンポーネントに寄せ、
  LP とゲームの両方がそれを使う。重複するのは「進行の管理」だけに限定する
