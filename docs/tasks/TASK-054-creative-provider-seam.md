# TASK-054: Creative provider の継ぎ目（本物の広告への差し替え口）

## メタデータ
- 作成日: 2026-09-14
- 更新日: 2026-09-14
- 状態: 未着手
- 進捗: 0%
- 依存: TASK-052（blocker）, TASK-053（推奨: 実測値が無いと器の寸法が決まらない）

## 目的
将来「本物の広告を使えることが見えてきたら簡単に切り替えられる」ようにする（オーナー方針
2026-09-14）。切替時の変更範囲を creative 層に閉じ込め、engine・採点・テストを無改修に保つ。

## 変更範囲
- `packages/ui/src/shells/*`（器と中身の分離。中身の差し込み口を作る）
- `apps/web/src/game/`（provider の解決）
- `AdSlot` の `provider: 'simulated' | 'network'`（ADR-012 で定義済みの型をゲーム側へ通す）

## 禁止事項
- **engine（`packages/game-engine`）が creative の中身を参照すること。** 決定論とリプレイが壊れる
- 閉じるボタン・ライフサイクル・重なり順を creative 側に委ねること。SAFE-01 が検証不能になる
- 既定値を `network` にすること。既定は常に `simulated`

## 完了条件
- [ ] 器（枠・ラベル・閉じるボタン・ライフサイクル）と中身（表示物）が型レベルで分離されている
- [ ] `provider` を切り替えても engine のリプレイ回帰フィクスチャが 1 件も変化しない
- [ ] `provider` を切り替えても SAFE-01（必ず閉じられる）のプロパティテストが通る
- [ ] ゲームルートで `provider: 'network'` が型・静的検査により拒否される（SAFE-13 の既定値を維持）
- [ ] 切替手順が `AD_ANATOMY.md` または ADR-013 に書かれている

## テスト方法
- 単体: provider 差し替え時の器の不変性
- 回帰: `pnpm --filter @ad-jigoku/game-engine test`（リプレイフィクスチャが不変であること）
- プロパティ: SAFE-01 を両 provider で 300 seed
- 静的: SAFE-13 の検査がゲームルートに対して落ちること（意図的な違反を入れて確認）

## 停止条件
共通のもののみ。加えて、器と中身の分離によって既存のパターン表現力が落ちる場合
（例: 中身と枠が一体でないと成立しないパターンがある）は、停止して ADR-013 を改訂する。

## 決定ログ
- 2026-09-14: 「器は常に自前、中身だけ差し替え」という分割を採用。これにより本物の広告を入れても
  engine が中身を知る必要がなく、決定論・リプレイ・SAFE-01 が provider に依存せず成立する
  （却下案: 広告まるごとを実配信に委ねる。理由: engine が閉じられるタイミングを知れず、採点も
  リプレイも安全性保証も成立しなくなる）
